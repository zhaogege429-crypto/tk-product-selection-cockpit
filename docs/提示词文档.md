# 提示词文档

## 1. 文档目的

本文档说明 `TK选品指挥舱` 当前如何组织提示词、怎样约束模型输出，以及后续如何优化提示词稳定性与业务贴合度。

## 2. 当前提示词架构

当前实现位于 `src/App.tsx`，由三部分组成：

| 层级 | 作用 | 当前实现 |
| --- | --- | --- |
| 系统提示词 | 设定角色、目标、判断原则和输出要求 | 常量 `systemInstruction` |
| 用户提示词 | 将表单字段整理为待分析产品信息 | `userPrompt` |
| 结构化约束 | 强制模型按固定 JSON Schema 输出 | `responseSchema` + `responseMimeType: application/json` |

## 3. 当前系统提示词目标

系统提示词把模型限定为“TK选品判断智能体”，并明确它不是泛电商顾问，而是站在 TikTok 电商操盘手视角做判断。它要求模型必须围绕以下三件事回答：

1. 产品是否适合在 TikTok 生态中销售。
2. 更适合短视频带货、直播带货、达人分销，还是不建议做。
3. 核心卖点、成交逻辑和运营风险分别是什么。

## 4. 当前系统提示词的核心约束

### 4.1 判断原则

当前提示词中明确了以下约束：

1. TikTok 适合的是“能被内容卖出去的货”。
2. 优先看内容表现力、卖点理解门槛、冲动消费属性、转化效率、售后与合规风险。
3. 不能因为产品便宜就默认适合 TK。
4. 不允许只给模糊建议，必须明确分级。
5. 信息不足时不能拒绝回答，而是要先说明缺失信息，再给初步判断。
6. 所有结论都要先结论，再原因，再建议。
7. 禁止编造平台内部数据或虚假行业数据。
8. 输出风格必须像 TikTok 卖货操盘手。

### 4.2 判断维度

当前提示词要求模型围绕五个维度判断：

| 维度 | 判断重点 |
| --- | --- |
| 内容可卖性 | 是否有展示感、对比感、结果感，是否适合前 3 秒抓人 |
| 成交可转化性 | 是否能一句话讲清卖点，是否低门槛冲动下单 |
| 流量可放大性 | 是否适合自然流、投流、达人分发、直播承接 |
| 风险可控性 | 是否存在退货、夸大宣传、合规、教育成本高等问题 |
| 货盘角色判断 | 更像引流款、爆款、利润款、福利款还是测款 |

## 5. 当前用户提示词拼装方式

前端会把表单数据拼成一段统一的产品描述，当前字段如下：

1. 产品名称/链接/图片描述
2. 类目
3. 售价或价格带
4. 核心卖点
5. 使用场景与目标人群
6. 补充信息与已测结果

当前特点：

1. 用户输入为空时，会用“未提供”补位。
2. 只要名称、类目、卖点三者有一个非空，就允许发起分析。
3. 用户提示词本身不包含复杂推理要求，主要由系统提示词承担业务约束。

## 6. 当前输出结构

模型必须输出一个 JSON 对象，字段结构如下：

```json
{
  "conclusion": {
    "level": "优先做 | 可以测试 | 谨慎进入 | 不建议做",
    "summary": "一句话结论摘要"
  },
  "adaptability": {
    "contentSellability": "高 | 中 | 低",
    "conversionPotential": "高 | 中 | 低",
    "trafficScaling": "高 | 中 | 低",
    "riskLevel": "高 | 中 | 低",
    "reasons": ["核心原因1", "核心原因2"]
  },
  "recommendedPath": {
    "path": "短视频自然流 | 短视频付费投流 | 达人分销 | 直播带货 | 组合打法 | 暂不建议",
    "reason": "推荐原因"
  },
  "sellingPoints": ["卖点1", "卖点2"],
  "operationsAdvice": ["建议1", "建议2"],
  "missingInfo": {
    "missingFields": ["缺失字段1"],
    "impact": "缺失信息造成的影响"
  }
}
```

## 7. 当前模型调用参数

| 参数 | 当前值 | 说明 |
| --- | --- | --- |
| 模型 | `gemini-3.1-pro-preview` | 写死在前端代码中 |
| 温度 | `0.2` | 偏低，强调稳定和分析性 |
| 输出格式 | `application/json` | 尽量减少自由文本飘逸 |
| 结构化约束 | `responseSchema` | 用于保证字段齐全 |

## 8. 当前提示词方案的优点

1. 角色清晰，模型不会轻易滑向泛化电商分析。
2. 输出结构固定，前端展示稳定。
3. 对“信息不足但仍需判断”做了明确约束，符合真实业务场景。
4. 已经把 TikTok 场景里的关键判断语言固化下来，便于团队统一口径。

## 9. 当前提示词方案的不足

1. 没有区分类目，不同类目的风险和表达逻辑还没做专门增强。
2. 没有接入案例示例，模型风格主要依赖系统描述，稳定性有限。
3. 没有输出置信度，用户难判断结论把握度。
4. 没有对“价格、毛利、物流、侵权、功效词”等风险做规则级补充。
5. 没有对不同业务角色输出不同话术，例如老板版、投手版、达人商务版。

## 10. 建议的提示词优化方向

### 10.1 短期可优化

1. 增加 few-shot 示例，让模型更稳定地区分“优先做”和“可以测试”。
2. 增加“反例”约束，明确哪些情况必须判定为“不建议做”。
3. 把价格带、客单价、复购属性、退货风险写成更明确的判断规则。
4. 把“卖点提炼”要求收紧为更像脚本钩子语句，而不是泛描述。

### 10.2 中期可优化

1. 做类目专属提示词，例如美妆、3C、服饰、家居分别强化风险点。
2. 引入多阶段提示词链路，先判断是否适合，再生成打法与卖点。
3. 在结构化输出中增加“反对立项的关键原因”字段，方便快速拍板。

### 10.3 长期可优化

1. 将提示词与规则库结合，形成“模型判断 + 规则兜底”的混合系统。
2. 引入产品图片、视频脚本、竞品页面等多模态输入。
3. 引入历史测品反馈，形成闭环优化。

## 11. 建议的提示词维护规范

1. 系统提示词改动前，先保留旧版本，避免结果风格突然漂移。
2. 每次改动都要准备一组固定测试样本做对比验证。
3. 输出结构不要随意变动，否则前端解析和展示会被破坏。
4. 如果新增字段，必须先同步更新 `src/types.ts`、`responseSchema` 和展示组件。

## 12. 提示词版本建议

### 12.1 当前版本定义

一个强调“TikTok 业务判断”和“结构化输出”的单轮提示词系统。

### 12.2 下一步建议

1. 增加至少 6 个标准样例覆盖好货、一般货、风险货。
2. 把提示词文案从代码中抽离成独立配置，方便维护和 AB 测试。
3. 增加版本号和变更记录，例如 `Prompt v1.0 / v1.1`。
