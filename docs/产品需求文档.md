# 产品需求文档

## 1. 文档目的

本文档用于明确 `TK选品指挥舱` 当前产品要解决的问题、目标用户、核心能力、功能边界和后续演进方向，避免团队在“AI 能分析什么”和“产品真正要帮业务做什么”上出现偏差。

## 2. 产品概述

| 项目 | 内容 |
| --- | --- |
| 产品名称 | TK选品指挥舱 |
| 产品定位 | 面向 TikTok 电商团队的 AI 选品决策助手 |
| 核心价值 | 用接近一线操盘手的判断框架，快速评估一个产品在 TikTok 生态中的可卖性、放大路径和主要风险 |
| 当前形态 | 单页 Web 工具，用户输入产品信息后实时生成结构化分析报告 |
| 当前版本范围 | 单次选品分析，不含用户体系、数据库、历史沉淀和自动抓数 |

## 3. 业务背景

TikTok 电商的选品不是传统货架电商的“搜需求、看供给”逻辑，而是“这个货能不能被内容卖出去”。很多团队在选品时会遇到四类典型问题：

1. 选品判断高度依赖个别人经验，新人很难快速上手。
2. 团队讨论时标准不统一，有人看利润，有人看内容感，有人只看同行销量。
3. 在立项前缺少一个能快速给出方向性判断的工具，导致测品成本高。
4. 即使判断“能卖”，也不清楚更适合短视频、直播还是达人分销。

本产品的目标不是替代完整经营分析，而是把“第一轮选品判断”做成可复用、可复制、可讨论的结构化流程。

## 4. 目标用户

| 用户角色 | 主要诉求 |
| --- | --- |
| 选品专员 | 快速筛掉明显不适合 TikTok 的产品，减少低质量测品 |
| 操盘手/项目负责人 | 在立项前快速判断内容打法和成交路径 |
| 投手/内容团队 | 明确卖点表达、前 3 秒素材切入点和放量可能性 |
| 老板/业务负责人 | 获得一个能统一团队判断语言的决策界面 |

## 5. 核心问题定义

产品需要帮助用户稳定回答以下问题：

1. 这个产品适不适合在 TikTok 生态中销售。
2. 这个产品应该优先用哪种流量/成交路径承接。
3. 这个产品的核心卖点是否容易被内容讲清楚。
4. 这个产品存在什么售后、合规或转化层面的主要风险。
5. 当前信息是否足够支持判断，缺了什么信息。

## 6. 产品目标

### 6.1 当前阶段目标

1. 让用户在 3 分钟内完成一次产品录入并拿到结构化研判。
2. 输出明确结论，避免“可以试试”这类模糊说法。
3. 把选品讨论统一到一套 TikTok 业务语言中。
4. 为后续测品、投流、达人分销和直播筹备提供第一步判断依据。

### 6.2 非目标

1. 不直接替代真实测品数据。
2. 不提供平台内部数据、销量预测或利润核算模型。
3. 不替代法务或合规审核。
4. 不承担 ERP、投放系统或 BI 系统的角色。

## 7. 核心能力定义

### 7.1 当前已实现

| 能力 | 说明 |
| --- | --- |
| 产品信息录入 | 支持录入产品名称、类目、价格带、卖点、人群和补充信息 |
| AI 结构化分析 | 基于固定系统提示词和 JSON Schema 生成标准化结果 |
| 结论分级 | 输出 `优先做 / 可以测试 / 谨慎进入 / 不建议做` |
| 适配性分析 | 输出内容可卖性、成交转化力、流量放大性、风险等级 |
| 路径建议 | 输出最适合的成交路径及原因 |
| 卖点提炼 | 输出适合内容表达的核心卖点 |
| 行动建议 | 输出阶段性执行建议 |
| 缺失信息提醒 | 当输入不足时，明确缺失字段与影响 |
| API Key 自定义配置 | 支持用户在前端录入 Gemini API Key |

### 7.2 建议后续补齐

| 能力 | 价值 |
| --- | --- |
| 商品链接解析 | 减少手工录入成本，提高实际使用率 |
| 图片/视频识别 | 更贴近 TikTok 选品场景，增强“内容感”判断 |
| 历史报告沉淀 | 支持复盘与团队共享 |
| 报告导出 | 支持复制为飞书/Notion/企微讨论材料 |
| 批量选品分析 | 支持选品池初筛 |
| 角色化输出 | 为老板、投手、达人商务输出不同版本结论 |
| 多模型/多提示词策略 | 提高稳定性，降低单模型依赖 |
| 风险规则库 | 对侵权、功效宣称、退货高风险类目做额外拦截 |

## 8. 关键用户流程

### 8.1 当前主流程

1. 用户打开产品页面。
2. 用户配置 API Key，或使用环境变量中的默认 Key。
3. 用户填写至少一个产品线索。
4. 用户点击“执行研判”。
5. 系统调用 Gemini 生成结构化 JSON。
6. 页面展示研判报告。
7. 用户复制结论、路径、卖点或建议，进入下一步业务动作。

### 8.2 关键交互要求

1. 输入门槛不能太高，允许信息不完整时先给初判。
2. 输出必须先给结论，再给原因，再给建议。
3. 风险和缺失信息要显式提示，不能埋在长文里。
4. 所有结论都要面向“TikTok 是否能卖”而不是泛电商逻辑。

## 9. 功能需求

### 9.1 输入模块

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 产品名称/型号 | 否 | 可以填产品名、型号、链接或图片描述 |
| 大类目 | 否 | 当前为固定选项 |
| 终端售价带 | 否 | 支持价格区间和补充说明 |
| 核心卖点描述 | 否 | 用于判断内容表现力和转化表达 |
| 使用场景与人群 | 否 | 用于判断目标受众和冲动消费属性 |
| 其他背景信息 | 否 | 用于补充测品结果、合规担忧、同行情况等 |

说明：当前逻辑要求“产品名称、类目、核心卖点”三者至少有一个非空，否则不给发起分析。

### 9.2 输出模块

| 模块 | 输出内容 |
| --- | --- |
| 司令部研判结论 | 分级结论 + 一句话摘要 |
| TK 生态适配分析 | 四个维度高/中/低判断 + 核心依据 |
| 最佳成交路径 | 推荐路径 + 路径原因 |
| 提炼核心卖点 | 1-3 条前 3 秒表达卖点 |
| 阶段性行动建议 | 1-3 条业务动作建议 |
| 评估降级警告 | 缺失字段 + 缺失影响 |

## 10. 成功标准

### 10.1 当前阶段建议关注

1. 用户是否能在首次打开后顺利完成一次分析。
2. 输出是否足够明确，能直接支持“做/不做/怎么做”的讨论。
3. 团队是否愿意把报告内容复制到日常选品会议中使用。
4. 用户是否频繁因为 API Key、报错或结果不稳定而中断流程。

### 10.2 后续可量化指标

1. 单次分析完成率。
2. 报告复制使用率。
3. 同一团队重复使用率。
4. 被判定“优先做/可以测试”的产品后续测品转化情况。

## 11. 风险与约束

| 风险/约束 | 当前情况 |
| --- | --- |
| 模型稳定性 | 结论质量依赖模型输出稳定性 |
| 前端直连模型 | 适合轻量内部工具，不适合强安全要求场景 |
| 结果可解释性 | 已通过结构化字段改善，但仍是模型判断 |
| 数据输入质量 | 输入过少会导致判断降级 |
| 业务边界 | 该工具提供研判，不直接提供平台真实数据 |

## 12. 版本建议

### 12.1 V1.0 当前定义

一个能完成“单品录入 -> AI 研判 -> 结构化输出”的内部选品辅助工具。

### 12.2 V1.1 建议方向

1. 增加链接解析和图片理解。
2. 增加报告存档和再次编辑能力。
3. 增加固定场景模板，例如“达人分销预判”“直播福利款预判”。

### 12.3 V2.0 建议方向

1. 引入后端代理和团队账号体系。
2. 接入外部商品数据与投放数据。
3. 建立类目风控知识库和可解释规则层。
