# 项目说明文档

## 1. 项目简介

`TK选品指挥舱` 是一个前端单页应用，目标是让 TikTok 电商团队把选品讨论从“靠感觉”变成“有统一结构的判断”。系统当前通过用户输入产品信息，调用 Gemini 模型生成结构化选品报告。

## 5. 本地运行方式

### 5.1 前置条件

1. 已安装 Node.js。
2. 已具备可用的 Gemini API Key。

### 5.2 运行步骤

1. 安装依赖：`npm install`
2. 基于 `.env.example` 新建 `.env.local` 并填写 `GEMINI_API_KEY`
3. 启动开发环境：`npm run dev`
4. 打开地址：`http://localhost:3000`

### 5.3 可用脚本

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 启动本地开发环境 |
| `npm run build` | 生成生产构建 |
| `npm run preview` | 预览生产构建 |
| `npm run lint` | 执行 TypeScript 类型检查 |
| `npm run clean` | 清理构建产物 |

## 6. 环境变量说明

| 变量名 | 是否必需 | 说明 |
| --- | --- | --- |
| `GEMINI_API_KEY` | 是 | Gemini 模型调用所需 |
| `APP_URL` | 否 | 模板保留字段，当前业务未实际使用 |

说明：当前实现同时支持用户在前端弹窗里录入 API Key，录入后会保存到浏览器 `localStorage`。

## 7. 当前系统工作方式

1. 用户在左侧录入产品信息。
2. 用户点击“执行研判”。
3. 前端读取本地保存的 API Key，或退回到环境变量里的 Key。
4. 前端直接调用 Gemini 模型。
5. 模型返回 JSON。
6. 前端解析 JSON，并在右侧仪表盘展示结果。

## 8. 当前工程特点

### 8.1 优点

1. 结构简单，适合快速验证产品价值。
2. 没有后端依赖，部署和开发成本低。
3. 使用 TypeScript + Schema 约束，输出结构清晰。

### 8.2 现阶段限制

1. API Key 暴露在前端使用链路中，不适合强安全场景。
2. 没有数据库，报告无法自动留存。
3. 没有服务端兜底，无法做统一日志、限流和风控。
4. 没有业务规则层，结论完全依赖模型输出。

## 9. 适用场景

当前版本更适合以下场景：

1. 内部团队试用和原型验证。
2. 操盘手个人使用或小团队共识讨论。
3. 作为后续正式系统的业务验证前台。

当前版本不适合以下场景：

1. 面向大量外部用户直接开放。
2. 对数据审计、权限控制、安全合规要求高的商用环境。
3. 需要沉淀大量历史分析记录的正式中后台系统。

## 10. 建议的后续工程方向

### 10.1 短期

1. 把提示词与模型参数从页面代码中抽离。
2. 增加报告复制、导出和历史记录。
3. 增加错误日志和基本埋点。

### 10.2 中期

1. 引入后端代理层，隐藏 API Key。
2. 增加用户体系、团队空间和报告存档。
3. 增加链接解析、图片理解和规则引擎。

### 10.3 长期

1. 接入外部商品数据和内容数据。
2. 建立选品知识库与训练反馈闭环。
3. 形成完整的选品决策工作台，而不是单次问答工具。
